# Prospective G3 long-QA alternate (2026-11-02)

The retained B7 audit does not contain original chunk bytes, full prompt hashes, or task gold; this is an explicitly constructed **alternate**, not reconstructed B7 or observed serving traffic. It combines the earlier source-bound ZeroSCROLLS MuSiQue selection, distinct SQuALITY and NarrativeQA questions, and L-Eval legal, natural, narrative, longchat and meeting examples. For ZeroSCROLLS, the original question is copied before the intact original prompt; for L-Eval, the original instruction and document are rendered into a question-first prompt. These are new prompt templates. Original documents, questions and first retained answers are not altered. Long documents above the declared 180,000-character search bound are excluded rather than truncated. The selection files contain source line identities and hashes, never raw prompts or targets.

A vocabulary-only Qwen3.8-27B tokenizer produced 885 valid requests; the fixed SHA-256 request-ID split gives 695 gate requests in four token-length buckets: **337, 208, 77, 73**. Each retained request has 2–16 non-overlapping exact-token chunks, each observed under at least two different token predecessor histories or offsets. `g3_manifest.py` checks these conditions and binds corpus/task hashes; `manifest.json` SHA-256 is `f4ff9bc483acb5ec7362626c64ee722f847ea70d0933de9667dd046a582195b8`. The structural count is not a task-quality or gate result.

The exact-token-match task scorer is a diagnostic and is **not admitted** for these free-text QA/summarization targets. Multiple source references are reduced to the first retained target where applicable. This corpus has **not been selected or approved** as the B7-derived gate, and no measurement threshold is altered. The tokenizer loaded GGUF vocabulary only; no model inference or quality result was produced. Qwen3.8 metadata/vocabulary header SHA-256 is `bc85f42a131e0aab2ca3e661859588b9b39101c803cb6d87bb4dab3afa978e92` over 10,996,704 bytes; it does not establish a whole-model digest. The 35B and 30B roles were independently retokenized and structurally checked as described below.

The private, source-reconstructible token corpus and targets are retained at `/mnt/raid0/llm/tmp/kv-prefix-fork/kpf62-leval-final-20261102/`, with a host-Micron backup at `/mnt/micron/rtg58-kpf62-g3-alternate-20261102/` (host mount namespace). Source task content is not included in this public repository.

Reproduction: run `g3_longqa_acquire.py` first on SQuALITY and NarrativeQA sources, supplying the existing MuSiQue alternate via `--music`; then run it on the five recorded L-Eval source JSONLs with the first output via `--music`. ## Other roles and token-boundary alignment

The 35B-A3B MTP vocabulary independently reproduces 885 requests with gate bucket counts **337 / 208 / 77 / 73**; `manifest-35b.json` SHA-256 is `29d422b68b77650ea5915c6fe59c204487a4c7046d89356487a05e48e6988346`. Its separate model-header, tokenizer and library identities are in `report-35b.json`. The matching token hashes describe those vocabularies, not the identity of the 35B weights.

The first 30B-VL materialization using strict independent-prefix tokenization refused the bucket requirement (**327 / 17 / 14 / 12**): many source byte-span endpoints were not tokenizer boundaries. `g3_vocab_tokenize_aligned.cpp` addresses this without changing prompts or answers: it decodes every full-prompt token back into exact bytes, refuses if they do not reconstruct the entire input, and trims only the portions of a candidate cached chunk that fall inside its edge tokens. Trimmed edge tokens remain present in the full prompt; they are not claimed as reused. Its output reports the number of bytes trimmed at each end. Token-level repeated-chunk and held-out checks are then rerun on the actual selected token sequences. A 30B vocabulary-only smoke reconstructed its real prompt and produced two aligned chunks.

The resulting 30B candidate has **1,172 requests**, with gate buckets **337 / 275 / 183 / 125**. `manifest-30b.json` SHA-256 is `bf036c01ccace0ee1ea980b48f8a956c54f2a743a5c601fd5106e602f720273f`; its model-header, aligned-tokenizer and library pins are in `report-30b-aligned.json`. The earlier rejected `report-30b-unaligned.json` remains for audit. Different retained request counts reflect vocabulary-specific token boundaries and length filters, not a same-cohort comparison. Neither structural result admits the prospective source or exact-token task metric for a decision.

The full 35B and aligned 30B token corpora/targets remain in private host-Micron directories `/mnt/micron/rtg58-kpf62-g3-35b-20261102/` and `/mnt/micron/rtg58-kpf62-g3-30b-aligned-20261102/`. `g3_allroles_prospective.sh` reproduces their three-stage materialization under a CPU/RAM claim; select the aligned helper with `KPF62_VOCAB_HELPER`. The helper must be built from this candidate source against its own linked llama/ggml libraries and its digest verified before use.
